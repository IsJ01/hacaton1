# Основной бэкенд «Эко-Щит Каспия»

FastAPI, контракт v2, порт 8001. Принимает события от эмулятора буя, анализирует и отдаёт фронту.

```
эмулятор (:8000) ──POST──► бэкенд (:8001) ──GET──► фронт (:3000)
```

| Что пришло | Как анализируется | Результат |
|---|---|---|
| звук (`POST /api/v1/events`, `/classify`, `/classify/upload`) | обученная модель `../ml/models/classifier.pkl` | `SoundEvent` |
| солёность (`POST /api/v1/salinity`) | отклонение от нормы 12.5 ‰ на 2 ‰ и больше | `WaterEvent` `illegal_discharge` |
| снимок (`POST /api/v1/satellite`) | поиск тёмно-бурого пятна на воде (правило по цвету) | `WaterEvent` `illegal_discharge` |

Прогноз: `GET /api/v1/forecast?days=7` — вероятность присутствия тюленя у каждого буя по дням
и приоритет патрулирования (`risk_level`: low / medium / high). Параметры: `days` (1–7), `buoy_id`.

Телеметрия и аналитика (сверх контракта v2) — фронту не нужны заглушки:
- `POST /api/v1/telemetry` — `buoy_id`, `water_temp_c`, `level_m` (м, Балтийская система). Отклонение уровня
  от `LEVEL_NORM_M` (−28.9) на `LEVEL_THRESHOLD_M` (0.3 м) и больше → `WaterEvent` `level_anomaly`.
  `GET /api/v1/telemetry?buoy_id=` — история.
- `GET /api/v1/buoy-status` — статус каждого буя **за сутки**: `critical` (лодка, выстрел, сброс, аномалия
  уровня), `anomaly` (аномальный звук, солёность отклонилась на ≥1 ‰), `normal`; плюс причина, радиус
  слышимости (`listen_radius_km` из `buoys.json`), последние солёность, температура, уровень, `online`.
- `GET /api/v1/events/{id}/neighbors` — какие соседние буи слышали тот же класс звука в пределах ±10 мин.
  «Соседний» — зоны слышимости пересекаются. `verdict`: `confirmed` | `unconfirmed` (возможно ложное) | `isolated`.
  `GET /api/v1/water-events/{id}/neighbors` — то же для сброса: у кого рядом отклонилась солёность.
- `GET /api/v1/seals?hours=24` — тюлени: сколько раз и какие буи их слышали, группы (буи с пересекающимися
  зонами), центр группы, трек и дрейф (направление, км, км/ч), оценка численности снизу (пик вокализаций за час).

Демо (сверх контракта v2):
- При старте с пустой базой бэкенд сам создаёт историю за сутки: 27 звуков через настоящую модель
  (тюлени смещаются от буя 5 к бую 3, у буя 3 лодка и выстрел, у буёв 1 и 4 аномальные звуки),
  солёность, температура и уровень каждые 30 минут. Отключить: `DEMO_SEED=0`. Начать заново: `bash docker.sh reset`.
- `POST /api/v1/demo/scenario` — сценарий «браконьер» (~23 с): лодка у буя 1 → та же лодка у буя 2 →
  выстрел у буя 2 → выстрел у буя 3 → солёность 9.6 ‰ у буя 3. Кнопка на дашборде в «Режиме демо».
- `GET /api/v1/model-info` — метрики моделей для вкладки «О системе».

## Запуск

Мок из `mock-backend` занимает тот же порт 8001 — вместе они не работают.

```bash
bash docker.sh          # Docker (рекомендуется) → http://localhost:8001/docs
bash docker.sh logs     # логи
bash docker.sh stop     # остановить
bash docker.sh reset    # остановить и стереть данные
```

Без Docker: `bash run.sh` (нужен Python 3.10–3.12).

Первая сборка долгая: ставятся librosa и scikit-learn.

## Файлы

- `main.py` — все ручки API.
- `sound.py` — классификация звука моделью.
- `satellite.py` — анализ снимка.
- `forecast.py` — прогноз присутствия тюленя (модель `../ml/models/seal_forecast.pkl`).
- `analytics.py` — статус буя за сутки, соседи события, тюлени.
- `demo.py` — демо-история и сценарий «браконьер».
- `storage.py` — база SQLite (`data/eco.db`), данные переживают перезапуск.
- `config.py` — настройки (пороги, пути); любая меняется переменной окружения.
- `buoys.json` — список буёв: отсюда их получают и фронт, и эмулятор.
- `data/` — база, сохранённые звуки и снимки (создаётся сама, в git не попадает).

## Важно знать

- Модель обучена на звуках из `ml/data`. Звуки из `mock-backend/sounds` сделаны другим
  генератором, и модель их путает. Для демо скопируй в эмулятор звуки из датасета:
  `cp ../ml/data/*/*_00[0-2].wav ../mock-backend/sounds/`
- У модели 5 классов, в контракте 4 метки. Класс `background` отдаётся как `anomaly`.
- Библиотека для `/classify` и для `/events` без `audio` — папка `ml/data`
  (имена вида `seal_000.wav`).
- Событие `level_anomaly` бэкенд не создаёт: в контракте нет входных данных об уровне воды.
- Модель прогноза обучена на синтетических данных (`ml/forecast/train_forecast.py`), ответ помечен
  полем `training_data: "synthetic"`. Переобучить: `cd ../ml && python forecast/train_forecast.py`.
- Погоду для прогноза бэкенд берёт из Open-Meteo (нужен интернет). Без связи подставляет
  климатическую норму, в ответе это видно по `weather_source: "climatology"`.
  Совсем отключить запросы наружу: переменная `USE_WEATHER_API=0`.
- Старт пустой: история появляется, когда эмулятор начинает слать события.
