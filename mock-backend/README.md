# Эко-Щит Каспия — эмулирующий бэкенд (контракт v2)

Мок-сервер, который реализует API-контракт v2 целиком (звук, солёность, спутник, события воды),
и эмулятор буёв/спутника. Моделей нет: все «анализы» — заглушки, данные в памяти.

## Запуск в Docker

    bash docker.sh         # собрать образ и запустить бэкенд в фоне
    bash docker.sh emu     # бэкенд + эмулятор, который шлёт данные каждые 3 с
    bash docker.sh logs    # логи бэкенда
    bash docker.sh stop    # остановить

Скрипт использует обычные `docker build` / `docker run`, плагин compose не нужен.
Если `permission denied` на docker.sock — запускай через `sudo bash docker.sh`.

Если установлен плагин compose (`sudo apt install docker-compose-v2`), можно и так:

    docker compose up --build
    docker compose --profile emu up --build

Swagger: http://localhost:8000/docs
С другого устройства в той же сети: http://<IP-компьютера>:8000

## Запуск без Docker

    ./run.sh

## Настройки (переменные окружения)

| Переменная           | По умолчанию | Что делает                                                        |
|----------------------|--------------|-------------------------------------------------------------------|
| `PORT`               | 8000         | порт (только для run.sh)                                          |
| `SEED_EVENTS`        | 20           | звуковых событий при старте; 0 = пустой старт без всякой истории  |
| `AUTO_EMIT_SEC`      | 0 (выкл.)    | каждые N секунд сервер сам создаёт звук и солёность от буёв       |
| `SALINITY_NORM`      | 12.5         | нормальная солёность, ‰                                           |
| `SALINITY_THRESHOLD` | 2.0          | отклонение от нормы, с которого создаётся событие сброса          |
| `WATER_COOLDOWN_MIN` | 30           | один буй — не больше одного события сброса за N минут             |

В Docker: `AUTO_EMIT_SEC=5 bash docker.sh` или блок `environment` в docker-compose.yml.

## Эмулятор (buoy_emulator.py)

Шлёт данные на любой бэкенд с этим контрактом — на мок или на настоящий.
Каждый тик: звук от случайного буя, солёность от всех буёв; раз в 10 тиков — чистый снимок;
иногда «сброс»: солёность у одного буя падает на 5 тиков + приходит снимок с пятном.

    python3 buoy_emulator.py                          # тик 5 с
    python3 buoy_emulator.py --audio --interval 2     # звук с wav в base64
    python3 buoy_emulator.py --discharge-now          # сразу начать со сброса (для демо)
    python3 buoy_emulator.py --url http://host:8000 --count 20
    python3 buoy_emulator.py --no-sound --no-satellite   # только солёность
    python3 buoy_emulator.py --help

## Что есть при старте

- 5 буёв у побережья Дагестана.
- 20 звуковых событий за сутки.
- Солёность: 48 точек на буй за сутки (шаг 30 мин), у b-003 провал ~6 часов назад.
- 3 спутниковых снимка (один со сбросом у b-003).
- 3 события воды: сброс по солёности (b-003), сброс по снимку (b-003), аномалия уровня (b-005).

## Как устроены заглушки

**Звук.** Библиотека `library/` (8 wav, по 2 на класс) создаётся при старте. Файл из библиотеки →
класс из имени; чужой файл → класс из имени (`seal_…`, `boat_…`, `gunshot_…`, `anomaly_…`) или случайный.

**Солёность.** `|salinity − SALINITY_NORM| ≥ SALINITY_THRESHOLD` → `WaterEvent` типа `illegal_discharge`
с координатами буя. Повторные аномальные измерения того же буя в пределах 30 минут возвращают
то же событие, новое не создаётся.

**Спутник.** В `sat_library/` лежат 6 синтетических снимков: `clean_01..03.jpg`, `discharge_01..03.jpg`.
Файл из этой папки или с именем `discharge_*` / `spill_*` → сброс; `clean_*` → чисто; иначе случайно (35 %).
Если до ближайшего буя меньше 25 км, в событие подставляются его `buoy_id` и солёность на момент снимка.

## Отличия от контракта / что уточнить у команды

- Координаты буёв — побережье Дагестана (в примерах контракта 68.97, 33.07 — это Мурманск).
- Норма солёности 12.5 ‰ (Каспий), а в примерах контракта 34.2 — это океан. Если команда
  ориентируется на 34.2, поставь `SALINITY_NORM=34.2`.
- `level_anomaly`: в контракте нет эндпоинта, который принимает уровень воды. Мок создаёт одно такое
  событие при старте, чтобы фронту было что рисовать; новых не появляется.
- Сброс, замеченный и буем, и спутником, даёт два события воды (одно от солёности, одно от снимка);
  в событии от снимка заполнены оба поля `source`.
- В `details` и `source` неприменимые поля приходят как `null`.
- `GET /salinity` отдаёт последние `limit` точек по возрастанию времени (удобно для графика).
- `GET /events` и `GET /water-events` — новые события первыми.
- `source` у звукового события: `buoy`, `library`, `user`.
- Неизвестный `buoy_id` в POST → 404; ошибки валидации → 422; плохая дата/base64/координаты → 400.
  Формат всегда `{ "error": ..., "message": ... }`.
- Доп. эндпоинты: `GET /api/v1/library` (имена wav), `GET /api/v1/satellite` (список снимков).
- Загруженные файлы сохраняются как есть под `.wav` / `.jpg`, без перекодирования.
- Данные в памяти: перезапуск (и пересоздание контейнера) очищает историю.
