# Эко-Щит Каспия — эмулирующий бэкенд

Мок-сервер, который реализует API-контракт (все 8 эндпоинтов), и эмулятор буёв.
Модели нет: классификатор — заглушка, данные в памяти.

## Запуск

    ./run.sh

Swagger: http://localhost:8000/docs
С телефона/другого ноутбука в той же сети: http://<IP-компьютера>:8000

Вручную: `pip install -r requirements.txt && uvicorn main:app --host 0.0.0.0 --port 8000`

## Настройки (переменные окружения)

| Переменная      | По умолчанию | Что делает                                              |
|-----------------|--------------|---------------------------------------------------------|
| `PORT`          | 8000         | порт                                                    |
| `SEED_EVENTS`   | 20           | сколько событий за последние сутки создать при старте   |
| `AUTO_EMIT_SEC` | 0 (выкл.)    | каждые N секунд сервер сам создаёт событие от буя       |

Пример «живой» демки одним процессом: `AUTO_EMIT_SEC=5 ./run.sh`

## Эмулятор буёв (отдельный процесс)

Шлёт `POST /api/v1/events` на любой бэкенд с этим контрактом — на мок или на настоящий.

    python3 buoy_emulator.py                        # событие каждые 5 с, без аудио
    python3 buoy_emulator.py --audio --interval 2   # с wav из library/ в base64
    python3 buoy_emulator.py --url http://host:8000 --count 10

## Как устроена заглушка классификатора

- Библиотека `library/` создаётся при первом старте: `seal_01.wav`, `boat_01.wav`,
  `gunshot_01.wav`, `anomaly_01.wav` (по 2 файла на класс, синтетический звук).
- Файл из библиотеки → класс берётся из имени файла.
- Загруженный файл (`/classify/upload`) → класс из имени, если оно начинается
  с `seal_ / boat_ / gunshot_ / anomaly_`, иначе случайный.
- Аудио в base64 в `POST /events` → если это байт-в-байт файл из библиотеки, его класс; иначе случайный.
- `confidence` 0.72–0.98, в `candidates` все 4 класса, сумма ≈ 1.

## Отличия от контракта / что уточнить у команды

- Координаты буёв — побережье Дагестана (в примере контракта 68.97, 33.07 — это Мурманск).
- `source` у события: `buoy` (POST /events), `library` (/classify), `user` (/classify/upload).
  Результаты `/classify` и `/classify/upload` тоже попадают в историю `GET /events`.
- Неизвестный `buoy_id` в POST-запросах → 404 `not_found`.
- Ошибки валидации → 422 `{ "error": "validation_error", "message": ... }`, плохой base64/дата → 400 `bad_request`.
- `GET /events` отдаёт новые события первыми; `limit` максимум 500.
- Доп. эндпоинт `GET /api/v1/library` — список имён файлов для `/classify`.
- Загруженный с телефона файл сохраняется как есть под именем `.wav`, без перекодирования
  (браузер может записать webm/m4a — плеер в браузере обычно всё равно проиграет).
- Данные живут в памяти: перезапуск сервера очищает историю.
