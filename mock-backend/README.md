# Эко-Щит Каспия — эмулятор буя

    ты в Swagger (:8000)  ──►  эмулятор берёт файл из sounds/  ──►  POST на бэкенд (:8001), как настоящий буй

В папке два сервиса:

| Файл          | Что это                                                                 | Порт |
|---------------|-------------------------------------------------------------------------|------|
| `emulator.py` | **эмулятор буя** — из Swagger выбираешь буй и файл, он шлёт событие на бэкенд | 8000 |
| `main.py`     | мок основного бэкенда по контракту v2 — чтобы проверять эмулятор, пока настоящего нет | 8001 |

## Запуск эмулятора

    bash run.sh                                          # без Docker
    bash docker.sh                                       # в Docker

Swagger: http://localhost:8000/docs
Бэкенд по умолчанию — `http://localhost:8001`. Другой адрес:

    BACKEND_URL=http://192.168.1.50:8001 bash run.sh     # или bash docker.sh

Если настоящего бэкенда ещё нет, подними мок на 8001 во втором терминале:

    bash run_mock.sh          # или bash docker.sh mock

Остальное в Docker: `bash docker.sh logs`, `bash docker.sh logs mock`, `bash docker.sh stop`.
Если `permission denied` на docker.sock — `sudo bash docker.sh`.

## Демо на реальном бэкенде (без заглушек)

Бэкенд стартует пустым. Данные ему отправляет этот эмулятор — теми же запросами, что настоящие буи.

1. `cd ../backend && bash docker.sh reset && bash docker.sh` — бэкенд на 8001 с чистой базой.
2. `bash docker.sh` — эмулятор на 8000.
3. Swagger эмулятора http://localhost:8000/docs:
   - **`POST /check`** — проверка: отправить звук, солёность и телеметрию и прочитать их обратно
     через GET бэкенда. Все строки ✓ — бэкенд принимает данные буя.
   - **`POST /scenario/history`** — сутки работы пяти буёв (≈ 510 запросов, пара секунд):
     тюлени смещаются от буя 5 к бую 3, ночью лодка и выстрел у буя 3, аномальные звуки у буёв 1 и 4,
     солёность, температура и уровень каждые 30 минут, два спутниковых снимка.
     В ответе видно, сколько принято, что ответила модель и где она ошиблась (`model_mismatches`).
     Запускать один раз: повтор добавит данные ещё раз.
4. Дашборд http://localhost:3000 → «Режим демо» → **▶ Сценарий «браконьер»**: фронт просит эмулятор
   (`POST /scenario/poacher`), и тот за ~30 с шлёт лодку → ту же лодку у соседнего буя → выстрел →
   выстрел у соседа → падение солёности → снимок с пятном. Ход — `GET /scenario/status`.

Что и когда отправлять — в `scenarios.py`. Звуки там только те, что модель распознаёт уверенно:
файлы `*_01.wav`, `*_02.wav` сделаны другим генератором, и модель их путает.

## Как пользоваться (Swagger)

Раскрыть строку → **Try it out** → заполнить поля → **Execute**.

**Звук — `POST /send/sound`**
- `buoy_id` — от какого буя (список);
- `file` — имя файла из списка **или** `index` — порядковый номер из `GET /sounds`;
- ничего не выбрано — берётся случайный файл.

Эмулятор читает файл, кодирует в base64 и отправляет на бэкенд `POST /api/v1/events`:

    { "buoy_id": "b-001", "timestamp": "...", "audio": { "format": "wav", "data_base64": "..." } }

**Солёность — `POST /send/salinity`**
- `buoy_id`, `salinity` (число, ‰).

Уходит на бэкенд `POST /api/v1/salinity`:

    { "buoy_id": "b-003", "salinity": 12.4, "timestamp": "..." }

**Телеметрия — `POST /send/telemetry`**
- `buoy_id`, `water_temp_c` (°C), `level_m` (м, Балтийская система; отклонение от −28.9 на 0.3 м → аномалия уровня).

Уходит на бэкенд `POST /api/v1/telemetry`.

**Спутник — `POST /send/satellite`**
- `lat`, `lon`, `file` или `index` (снимки из `sat_library/`, список — `GET /images`).

Уходит на бэкенд `POST /api/v1/satellite` (multipart: `file`, `geo[lat]`, `geo[lon]`, `timestamp`).

В ответе каждого запроса видно: куда отправили (`to`), что отправили (`sent`),
код и тело ответа бэкенда (`backend_status`, `backend_response`).

| Ответ эмулятора | Что значит                                                     |
|-----------------|----------------------------------------------------------------|
| 200             | бэкенд принял событие                                          |
| 404             | нет такого файла/номера (в ответе список доступных)            |
| 502 `backend_unavailable` | бэкенд не отвечает по `BACKEND_URL`                  |
| 502 `backend_error`       | бэкенд ответил ошибкой (она в `backend_response`)    |

Служебное: `GET /health` (куда шлём, жив ли бэкенд), `GET /log` (журнал отправок), `GET /buoys` (буи с бэкенда).

## Папка со звуками

`sounds/` — готовые файлы. Сейчас там 8 синтетических примеров:
`seal_01/02.wav`, `boat_01/02.wav`, `gunshot_01/02.wav`, `anomaly_01/02.wav`.

Свои звуки просто копируй в `sounds/` (wav, mp3, ogg, flac, m4a) — перезапуск не нужен:
файл сразу виден в `GET /sounds` и отправляется по имени или номеру. В выпадающем списке Swagger
новый файл появится после перезапуска эмулятора. Номера идут по алфавиту имён.

## Настройки (переменные окружения)

| Переменная    | По умолчанию                       | Что делает                               |
|---------------|------------------------------------|------------------------------------------|
| `BACKEND_URL` | http://localhost:8001              | куда эмулятор шлёт события               |
| `PORT`        | 8000                               | порт эмулятора                           |
| `BUOYS`       | b-001,b-002,b-003,b-004,b-005      | буи в выпадающем списке Swagger          |
| `MOCK_PORT`   | 8001                               | порт мока                                |

## Автоматический поток (для живой демки)

`buoy_emulator.py` сам шлёт на бэкенд звук, солёность и снимки каждые N секунд:

    python3 buoy_emulator.py --audio --interval 3            # на http://localhost:8001
    python3 buoy_emulator.py --discharge-now                 # сразу разыграть сброс
    python3 buoy_emulator.py --url http://host:8001 --help

## Мок основного бэкенда (main.py)

Реализует контракт v2 целиком: буи, звуковые события, классификация, солёность, спутник, события воды.
Модели нет: класс звука берётся из имени файла (`seal_…`, `boat_…`, `gunshot_…`, `anomaly_…`), иначе случайный;
сброс по солёности — отклонение от 12.5 ‰ на 2 и больше; сброс по снимку — имя `discharge_*`.
Данные в памяти, при старте создаётся история за сутки. Настройки: `SEED_EVENTS`, `AUTO_EMIT_SEC`,
`SALINITY_NORM`, `SALINITY_THRESHOLD`, `WATER_COOLDOWN_MIN`.

Что в моке отличается от примеров контракта: координаты буёв — побережье Дагестана (в примерах Мурманск);
норма солёности 12.5 ‰ (в примерах 34.2); `level_anomaly` создаётся только одно при старте — в контракте
нет эндпоинта, принимающего уровень воды.
